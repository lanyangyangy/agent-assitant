# Frontend MVP Agent Console Design

## 目标

构建一个前端 MVP 控制台，用来真实连接已经完成的 FastAPI 后端，验证 Agent 能创建会话、发送消息、接收 SSE 流、展示工具调用与工具结果，并让使用者清楚看到当前后端健康状态。

第一版采用“三栏工作台”布局：左侧会话，中间聊天，右侧工具事件。全部验收通过后，再将主体验演进为“聊天优先”布局。

## 范围

本阶段只做前端系统 A 版：

- React + Vite 前端工程，放在 `frontend/` 目录。
- 可配置后端地址，默认连接本地后端。
- 用户输入 `X-User-Id`，用于调用后端用户隔离接口。
- 展示后端健康状态、模型配置状态、搜索可用状态。
- 创建、列出、切换、删除会话。
- 发送聊天消息到 `POST /chat/stream`。
- 解析 SSE 事件并流式更新聊天内容。
- 在右侧事件面板展示 `message_start`、`tool_call`、`tool_result`、`error`、`message_end`。
- 展示工具列表，并可查看工具名称、描述和参数。
- 提供中文界面、中文错误提示、中文空状态。

不在本阶段做：

- 用户登录系统。
- 多人协作。
- trace HTML/JSONL 可视化。
- 工具参数调试器。
- 前端持久化复杂同步。
- 切换到聊天优先 B 布局的最终实现。

## 技术路线

- `frontend/` 使用 React + Vite + TypeScript。
- 样式使用普通 CSS module 或集中 CSS 文件，避免引入大型 UI 框架。
- API 层封装在 `frontend/src/api/`，所有请求统一注入 `X-User-Id`。
- SSE 使用浏览器 `fetch` + `ReadableStream` 解析，因为 `EventSource` 不方便发送 POST body 和自定义请求头。
- 状态管理使用 React hooks 和小型 reducer，不引入 Redux/Zustand。
- 测试使用 Vitest + React Testing Library。
- 浏览器验收使用 Playwright，覆盖桌面和移动视口。

## 后端接口

前端依赖以下后端接口：

- `GET /health`
  - 用于顶部状态条。
  - 展示 `status`、`model_configured`、`sqlite_available`、`search_available`。

- `POST /sessions`
  - 请求头：`X-User-Id`
  - 创建当前用户会话。

- `GET /sessions`
  - 请求头：`X-User-Id`
  - 返回 `{ "sessions": [...] }`。

- `DELETE /sessions/{session_id}`
  - 请求头：`X-User-Id`
  - 删除当前用户自己的会话。

- `GET /tools`
  - 展示工具目录。

- `POST /chat/stream`
  - 请求头：`X-User-Id`
  - 请求体：`session_id`、`message`、可选 `metadata`
  - 响应：`text/event-stream`

SSE 事件类型：

- `message_start`
- `tool_call`
- `tool_result`
- `token`
- `message_end`
- `error`

## 信息架构

### 顶部状态栏

顶部状态栏展示：

- 产品名：`Agent 控制台`
- 当前后端地址
- 健康状态
- 模型状态
- 搜索状态
- 当前用户 ID 输入框
- 手动刷新按钮

用户 ID 默认为 `alice`。切换用户 ID 后，需要重新拉取该用户的会话列表。切换用户时不会把旧用户会话混入新用户状态。

### 左侧会话栏

左侧会话栏展示：

- 新建会话按钮
- 当前用户会话列表
- 当前选中会话状态
- 删除会话按钮
- 空状态提示

会话列表按后端返回顺序展示。创建新会话后自动选中新会话。删除当前会话后，如果还有其他会话，自动选中第一条；如果没有会话，聊天区进入空状态。

### 中间聊天区

中间聊天区展示：

- 当前会话 ID 的短显示。
- 消息列表。
- 用户消息气泡。
- 助手消息气泡。
- 流式回答中的实时 token。
- 发送输入框。
- 发送按钮。
- 正在生成状态。

发送时必须存在 `user_id` 和 `session_id`。输入为空时禁用发送。请求进行中时禁用重复发送，但允许用户继续编辑输入框。

### 右侧工具事件栏

右侧事件栏展示当前会话最近一次请求的事件：

- `message_start`：标记一次请求开始。
- `tool_call`：展示工具名、调用参数。
- `tool_result`：展示成功/失败、结果数据、耗时。
- `error`：展示错误信息。
- `message_end`：展示完成状态、是否保存 memory。

事件面板需要有清晰的时间顺序和状态颜色：

- 蓝色：开始、进行中。
- 黄色：工具调用。
- 绿色：成功结果。
- 红色：错误。
- 灰色：结束和普通信息。

工具参数和结果以格式化 JSON 展示，长内容可滚动。

### 工具目录

工具目录放在右侧栏底部或可折叠区域，展示：

- `calculator`
- `search`
- `get_weather`

每个工具显示描述和参数列表。第一版只读展示，不做直接调用表单。

## 视觉设计

采用“冷静工程台”风格：

- 浅色背景。
- 清晰边框和分区。
- 低饱和蓝灰作为主 UI 色。
- 黄色用于工具调用提示。
- 绿色用于成功状态。
- 红色用于错误状态。
- 8px 或更小圆角。
- 不使用营销式 hero、不使用大面积装饰渐变、不使用装饰光斑。

布局要求：

- 桌面端为三栏：左 260px，中间自适应，右 340px。
- 顶部状态栏固定在工作台上方。
- 主区域高度为视口剩余高度，聊天列表和事件列表各自滚动。
- 移动端改为上下结构：状态栏、会话选择、聊天区、事件折叠面板。
- 文本和按钮不得在 360px 宽度下溢出。

## 数据流

1. 应用启动后读取后端地址配置。
2. 调用 `GET /health` 和 `GET /tools`。
3. 使用默认用户 ID `alice` 调用 `GET /sessions`。
4. 如果没有会话，显示空状态，引导创建会话。
5. 用户创建或选择会话后进入聊天状态。
6. 用户发送消息：
   - 立即把用户消息加入本地消息列表。
   - 清空本次事件列表。
   - 调用 `POST /chat/stream`。
   - 收到 `message_start` 后记录请求开始。
   - 收到 `tool_call` 和 `tool_result` 后更新右侧事件栏。
   - 收到 `token` 后增量拼接助手消息。
   - 收到 `error` 后展示错误，并结束生成状态。
   - 收到 `message_end` 后结束生成状态。
7. 请求结束后保留消息和事件，方便检查。

## 错误处理

必须覆盖并显示中文错误：

- 后端不可达：`无法连接后端，请确认服务已启动。`
- 缺少用户 ID：`请输入用户 ID。`
- 没有选中会话：`请先创建或选择会话。`
- SSE 中断：`聊天流中断，请重试。`
- 后端返回 `error` 事件：展示后端 message。
- JSON 解析失败：`收到无法解析的流式事件。`
- 删除会话失败：`删除会话失败，请刷新后重试。`

错误不应让整个页面白屏。所有 API 调用失败都应落到局部错误提示。

## 测试策略

单元测试：

- API URL 拼接和请求头注入。
- SSE parser 能解析多行 event/data。
- SSE parser 能处理分块输入。
- reducer 能正确处理 `token` 拼接。
- reducer 能记录工具事件。
- reducer 能处理 `error` 并结束生成状态。

组件测试：

- 初始健康状态加载。
- 用户 ID 切换后重新加载会话。
- 新建会话后自动选中。
- 发送按钮在无会话或空输入时禁用。
- 收到 token 后聊天区实时更新。
- 收到 tool_call/tool_result 后右侧事件栏更新。

端到端测试：

- 启动后端和前端。
- 打开前端页面。
- 创建会话。
- 发送 `请计算 19 * 23 并解释结果`。
- 页面显示工具调用 `calculator`。
- 页面显示工具结果 `437`。
- 页面显示最终助手回答。
- 切换为 `bob` 后看不到 Alice 会话。

## 后续演进到 B 布局

当 A 版全部验收通过后，可以把布局演进为“聊天优先”：

- 中间聊天区扩大为主视觉。
- 工具事件改为消息下方的内联折叠详情。
- 右侧栏减少常驻信息，只保留状态和工具目录。
- A 版三栏仍可作为调试模式保留。

这次实现需要把布局组件和数据逻辑分离，避免后续切 B 时重写 SSE、会话和 API 层。

## 验收标准

前端 MVP 完成时必须满足：

- `frontend/` 可独立安装、启动、测试。
- 页面能连接本地后端并展示健康状态。
- 能输入用户 ID，并按用户隔离会话。
- 能创建、切换、删除会话。
- 能发送消息并解析真实 SSE。
- 能流式展示助手回答。
- 能展示工具调用和工具结果。
- 至少一次真实联调证明 `calculator` 被 Agent 调用，结果 `437` 被展示。
- 桌面和移动视口无明显布局溢出。
- 所有用户可见文本为中文。
- 所有新增代码注释为中文。
- 单元、组件、端到端测试通过。

- 已明确 A 版与后续 B 版的边界。
